# Kesalahan AI yang Kami Temukan

Catatan ini merekam kekeliruan, diagnosis yang belum lengkap, dan celah yang ditemukan saat meninjau hasil AI. Bedakan perbaikan yang sudah diverifikasi dengan pekerjaan yang masih perlu dilakukan; jangan menyatakan perbaikan selesai jika belum diuji.

| No | Apa yang diminta | Kesalahan AI / kekurangan hasil | Bagaimana kami mengetahuinya | Perbaikan yang kami lakukan / status |
|---|---|---|---|---|
| 1 | Perbaiki pesan “Tidak dapat terhubung ke API” pada frontend. | Perubahan awal pada URL/pesan API belum menjelaskan seluruh penyebab. Setelah backend aktif, browser masih gagal karena backend menolak origin frontend saat `APP_ORIGIN` kosong; tanpa header `Origin`, endpoint terlihat merespons normal sehingga pemeriksaan sederhana bisa menyesatkan. | Uji `curl` dengan `Origin: http://127.0.0.1:5500` menunjukkan preflight HTTP 403 dan JSON “Origin tidak diizinkan”, sementara permintaan tanpa origin berhasil. | Default development `APP_ORIGIN` dibatasi ke `http://127.0.0.1:5500`, README menjelaskan konfigurasi origin yang harus cocok, dan preflight/API kemudian diverifikasi memberi HTTP 204/200. Deployment tetap wajib menetapkan origin yang benar. |
| 2 | Catat dan jalankan pengujian proyek. | Dokumentasi kasus uji sebelumnya menyatakan tidak ada test runner, padahal `test/run.php` dan `test/frontend.test.js` sudah tersedia dan telah dijalankan. | Pemeriksaan file repository dan eksekusi `php test\run.php` serta `node --test test\frontend.test.js`. | `docs/04-kasus-uji.md` diperbarui dengan perintah dan hasil yang benar: 33 pemeriksaan backend dan 20 tes frontend pada validasi 16 Oktober 2026. |
| 3 | Buat navigasi onboarding dan pengujian slide. | Tes awal mengharapkan posisi slide pertama `translateX(0%)`, sedangkan implementasi menghasilkan `translateX(-0%)`. Secara tampilan keduanya setara, tetapi hasil string tidak sesuai kontrak tes. | Tes onboarding pertama gagal pada perbandingan string posisi slide pertama. | Implementasi mengeluarkan offset `0` secara eksplisit untuk slide pertama; seluruh tes frontend setelah perbaikan lulus. |
| 4 | Simpan status onboarding agar pengenalan tidak mengganggu kunjungan berikutnya. | Skrip onboarding menyimpan `geokbm_onboarding_done` ketika dilewati, tetapi belum membaca nilai itu saat halaman dibuka ulang. Akibatnya, pengenalan tetap mulai dari slide pertama setelah reload. | Peninjauan alur inisialisasi `src/frontend/js/onboarding.js`: status disimpan oleh tombol Lewati, namun nilai localStorage tidak dipakai untuk menentukan slide awal. | **Belum diperbaiki.** Perlu gunakan status tersimpan untuk menampilkan slide pilihan portal pada kunjungan berikutnya, lalu tambahkan tes reload untuk memastikan perilakunya. |
